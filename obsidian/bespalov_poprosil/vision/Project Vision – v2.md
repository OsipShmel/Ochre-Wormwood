
# Project Vision & Technical Manifesto: Intelligent Security Gate for CI/CD  
  
## 1. Executive Summary (Манифест)  
  
**Проблема:** Современный процесс разработки (CI/CD) перегружен результатами автоматического статического анализа (SAST). Специалисты по безопасности тратят колоссальное количество времени на разбор «шума» — ложных срабатываний или уязвимостей, которые технически существуют, но практически не могут быть эксплуатированы из-за особенностей архитектуры приложения.  
  
**Наше решение:** Мы создаем не просто ИИ-агента, а **автоматизированный контур верификации безопасности**. Наша система встраивается между результатами SAST и финальным решением человека, выполняя роль интеллектуального фильтра.   
  
**Наша цель — не заменить человека, а радикально повысить КПД его работы.** Мы превращаем вопрос *«Есть ли в коде потенциальная проблема?»* (ответ на который дает SAST) в глубокую аналитику:  
1.  *«Насколько эта проблема критична именно в данной архитектуре?»* (**Contextual Scoring**)  
2.  *«Можно ли её реально эксплуатировать прямо сейчас?»* (**AI Pentester**)  
  
> **Core Value Proposition:** Снижение нагрузки на Security-инженеров за счет автоматической приоритизации и практического подтверждения (PoC) наиболее значимых угроз.

## 2. Product Roadmap: От MVP к автономному агенту  
  
Развитие проекта разделено на два этапа, чтобы обеспечить быструю поставку ценности и минимизировать риски интеграции в закрытые контуры заказчика (ЦФТ).  
  
### Phase 1: The Intelligence Layer (MVP)  
**Фокус:** Интеллектуальный скоринг и первичная фильтрация.  
* **Интерфейс:** Независимый сервис («Standalone CLI/Web Tool»), принимающий кодовую базу, результаты SAST и метаданные архитектуры. Это позволяет тестировать логику без прямой интеграции в сложные CI/CD пайплайны на ранних этапах.  
* **Функционал:**   
* Прием результатов от существующих инструментов (Semgrep, CodeQL, Bandit).  
  * Построение упрощенного графа архитектуры на основе доступных метаданных проекта.  
    * **Contextual Scoring Engine:** Анализ связей между уязвимым узлом и критическими компонентами системы для переоценки приоритета.  
* **Результат:** Структурированный отчет с приоритизированным списком уязвимостей (High/Medium/Low) с обоснованием их значимости в контексте архитектуры.  
  
### Phase 2: The Autonomous Pentester (Target State)  
**Фокус:** Активная верификация через итеративный пентестинг.  
* **Интерфейс:** Глубокая интеграция в CI/CD-пайплайн заказчика (GitLab CI / Jenkins / TeamCity).  
* **Функционал:**  
    * **AI Pentest Agent:** Итеративный цикл: *Гипотеза $\to$ Генерация атаки $\to$ Запуск в песочнице $\to$ Анализ результата $\to$ Корректировка.*  
    * **Sandboxed Execution:** Поднятие изолированных инстансов (Docker + gVisor) для безопасного прогона сгенерированных тестов/эксплойтов.  
    * **Security Gate / Supervisor:** Контролируемый шлюз, обеспечивающий изоляцию агента и мониторинг его действий во внешней среде.  
* **Результат:** Подтвержденные кейсы эксплуатации (Proof of Concept) с техническими логами атаки для критических уязвимостей.

## 3. System Architecture & Components  
  
Система строится на принципе **Separation of Concerns** через оркестрацию специализированных компонентов.  
  
| Компонент | Роль | Входные данные | Выходные данные |  
| :--- | :--- | :--- | :--- |  
| **Mediator (Orchestrator)** | Управление жизненным циклом проверки | Код, метаданные, конфиг пайплайна | Итоговый структурированный отчет |  
| **Scoring Agent** | Контекстная приоритизация | SAST-результаты + Архитектурный граф | Приоритизированная очередь задач для пентеста |  
| **Pentest Agent** | Практическая верификация | Уязвимость + Контекст + Кодовая база | Подтвержденные эксплойты (PoC) или статус "не эксплуатируемо" |  
| **Security Gate (Supervisor)** | Безопасная среда и изоляция | Команды агента, сетевые запросы | Логи системы, очищенные результаты, контроль ресурсов |  
  
### Ключевые технологические решения:  
* **Runtime:** Python 3.14 + `uv` для эффективного управления зависимостями.  
* **AI Framework:** LangChain (и его экосистема) для построения агентских цепочек и планировщиков.  
* **Isolation:** Docker с использованием **gVisor** в качестве OCI-runtime для обеспечения глубокой изоляции ядра при выполнении потенциально опасных тестов.  
* **Architecture Mapping:** Использование графовых представлений (GNN или эмбеддинги узлов) для анализа связности компонентов и оценки векторов атак.

## 4. Output Standard (Стандарт выходных данных)  
  
Мы предоставляем не просто список предупреждений, а **многослойный отчет**, позволяющий специалисту мгновенно оценить реальный риск:  
  
1.  **Layer 1 (SAST):** Что нашел сканер? (Тип, место в коде).  
2.  **Layer 2 (Scoring):** Почему это важно здесь? (Связь с БД, доступность извне, влияние на соседние сервисы через цепочки уязвимостей).  
3.  **Layer 3 (Pentest):** Доказано ли это? (Описание сценария атаки, логи выполнения, технический статус: `EXPLOITABLE` / `NOT_REPRODUCIBLE`).

## 5. Project Boundaries (Границы ответственности)  
  
Для сохранения реалистичности и безопасности проекта мы четко определяем ограничения:  
* **Не замена человека:** Мы не принимаем окончательное решение о выпуске продукта. Решение всегда остается за специалистом.  
* **Не универсальный хакерский инструмент:** Наша цель — верификация конкретных векторов, обнаруженных SAST, а не бесконечный поиск новых путей взлома.  
* **Не гарантия абсолютной безопасности:** Отрицательный результат пентеста не означает отсутствие уязвимости — он лишь означает, что агент не смог ее эксплуатировать в текущей конфигурации среды.
