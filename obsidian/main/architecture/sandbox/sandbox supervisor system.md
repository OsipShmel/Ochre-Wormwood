2-х компонентная система управления песочницы, отвечающая за безопасный жизненный цикл изолированной среды, в которой выполняется Pentest Agent.

Основные задачи:

- контроль жизненного цикла и состояния sandbox и его внутренних процессов;
- обеспечение безопасного взаимодействия изолированной среды и внешнего мира;
- сбор и маршрутизация логов;
- контроль и ограничение действий агента;
- обеспечение агента условиями, необходимыми для выполнения его задачи(передача данных, создание и поддержание среды тестирования, оценка результатов, предоставление api для взаимодействия агента с системой);
- контроль аномального поведения;

---

## Архитектура разделяет ответственность между двумя уровнями:

[[sandbox-supervisor]] – внешняя по отношению к изолированной среде компонента. Имеет максимальные полномочия над песочницей, поддерживает прямую с остальной системой. В ответственность супервизора входит:
- Управление жизненным циклом песочницы(контейнер 1-го уровня)
- Контроль состояния среды 
- Агрегация логов от среды
- Связь с [[sandboxd]]

[[sandboxd]] (sandbox-runner )– находится внутри среды контейнера, выполняет всю грязную работу:
- Управление жизненным циклом контейнеров 2-го уровня
- Инициализация и поддержание среды
- Мониторинг контейнеров
- Сбор, агрегация и передача логов и телеметрии контейнеров
- Взаимодействие с агентом  

схему взаимодействия можно представить следующим образом:


```
                External / privileged layer
                ┌────────────────────────┐
                │ [[sandbox-supervisor]] │
                │                        │
                │ lifecycle of sandbox   │
                │ health / integrity     │
                │ logs aggregation       │
                │ destruction / restart  │
                └───────────┬────────────┘
                            │
                            │ controlled interface
                            ▼
                ┌────────────────────────┐
                │      [[sandboxd]]      │
                │                        │
                │ container lifecycle    │
                │ container monitoring   │
                │ local logs             │
                │ agent interaction      │
                └───────────┬────────────┘
                            │
             ┌──────────────┼──────────────┐
             ▼              ▼              ▼
          Agent          Target        auxiliary
         container       container      containers
         

```

Можно провести аналогию по функционалу и ответственности в докером:
- sandbox-supervisor ≈ dockerd
- sandboxd     ≈ containerd / shim

## Уровни реакции на аномалию
(примерный набросок)

#### Уровень 1 — Sandboxd

Если проблема относится к отдельному контейнеру:
```
agent container crashed
target container crashed
unexpected process
resource abuse
```

Runner пытается локально восстановить состояние:
```
restart
reset
recreate container
```

Теоретически на этом уровне демон может засечь проблему, говорящую о полной дискредитации sandbox – возможно предусмотреть сигнал супервизору.

#### Уровень 2 — Supervisor

Если проблема относится к самой sandbox или Sandboxd:

```
sandboxd malfunction
unexpected privileged behaviour
broken communication contract
invalid telemetry
integrity violation
runner compromise suspected
```

Supervisor считает sandbox потенциально скомпрометированной:

```
STOP
  ↓
DESTROY SANDBOX
  ↓
OPTIONAL RECREATE
```

Supervisor не должен пытаться восстановить доверие к потенциально скомпрометированной среде.

## Интерфейс Sandbox Runner ↔ Supervisor

Конкретный transport пока не фиксируется. Это может быть Unix socket, RPC, gRPC и т. п.
